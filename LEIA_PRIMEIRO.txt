================================================================================
                    EDUCA+ DIGITAL — LEIA PRIMEIRO
       Guia para abrir, entender, executar e modificar o protótipo
================================================================================

Este arquivo foi criado para quem está acessando o projeto Educa+ Digital pela
primeira vez, inclusive pessoas que ainda não possuem Flask ou as demais
bibliotecas Python instaladas.

O objetivo é que um novo programador consiga:

1. entender o que é o projeto;
2. preparar o computador;
3. instalar tudo o que o protótipo precisa;
4. executar o site localmente;
5. saber para que serve cada pasta e arquivo principal;
6. entender como os templates, CSS, JavaScript, backend e banco se conectam;
7. saber onde alterar cada parte sem criar arquivos desnecessários.

IMPORTANTE:
O Educa+ Digital é um projeto em desenvolvimento voltado principalmente para
pessoas idosas. A interface foi pensada para ser simples, acessível, guiada e
segura. Antes de alterar telas, cores, tamanhos, navegação ou interações, leve
em consideração acessibilidade, legibilidade e facilidade de uso.


================================================================================
1. RESUMO RÁPIDO — COMO RODAR O PROJETO PELA PRIMEIRA VEZ
================================================================================

Se você já possui Python instalado, o caminho mais rápido é:

1) Abra o terminal dentro da pasta do projeto.

2) Crie um ambiente virtual:

   Windows (PowerShell ou Prompt):

       python -m venv .venv

   Se o comando "python" não funcionar no Windows, tente:

       py -m venv .venv

3) Ative o ambiente virtual.

   Windows — PowerShell:

       .\.venv\Scripts\Activate.ps1

   Windows — Prompt de Comando (CMD):

       .venv\Scripts\activate.bat

   macOS/Linux:

       source .venv/bin/activate

4) Instale as dependências:

       python -m pip install --upgrade pip
       python -m pip install -r requirements.txt

5) Execute o projeto:

       python app.py

6) Abra o navegador e acesse:

       http://127.0.0.1:5000

Para parar o servidor, volte ao terminal e pressione:

       Ctrl + C

Pronto. Para a execução local básica, não é necessário instalar Flask
manualmente um por um: o arquivo requirements.txt instala Flask e as outras
bibliotecas utilizadas pelo projeto.


================================================================================
2. SE O COMPUTADOR AINDA NÃO TEM PYTHON
================================================================================

O backend do Educa+ é escrito em Python. Sem Python, o Flask não funciona.

Recomendação para desenvolvimento:

- Python 3.11 ou 3.12.

Depois de instalar o Python, feche e abra novamente o terminal e teste:

       python --version

No Windows também pode funcionar:

       py --version

O resultado deve mostrar algo semelhante a:

       Python 3.12.x

Se nenhum dos dois comandos funcionar, verifique se o Python foi adicionado ao
PATH do sistema durante a instalação.


================================================================================
3. O QUE É O AMBIENTE VIRTUAL (.venv)?
================================================================================

O ambiente virtual é uma pasta que guarda as bibliotecas Python utilizadas
somente por este projeto.

Ele evita misturar versões de Flask e outras bibliotecas com projetos diferentes.

Criar:

       python -m venv .venv

Ativar no PowerShell:

       .\.venv\Scripts\Activate.ps1

Quando estiver ativo, normalmente o terminal mostra algo parecido com:

       (.venv) C:\...\EDUCA_DIGITAL>

Para sair do ambiente virtual:

       deactivate

A pasta .venv NÃO deve ser enviada para o GitHub. Ela já está prevista no
.gitignore.


================================================================================
4. ERRO DO POWERSHELL AO ATIVAR O .venv
================================================================================

Em alguns computadores Windows, o PowerShell pode bloquear o script de ativação.
Nesse caso, há duas alternativas simples.

Alternativa A — usar o Prompt de Comando (CMD):

       .venv\Scripts\activate.bat

Alternativa B — liberar scripts apenas para o usuário atual no PowerShell:

       Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Depois tente novamente:

       .\.venv\Scripts\Activate.ps1

Se o computador pertencer a uma empresa ou instituição, respeite as políticas
de segurança do local antes de alterar essa configuração.


================================================================================
5. O QUE O requirements.txt INSTALA?
================================================================================

O arquivo requirements.txt é a lista oficial de dependências Python do projeto.
Atualmente ele contém:

- Flask
- requests
- edge-tts
- gunicorn
- psycopg[binary]

Para instalar tudo de uma vez:

       python -m pip install -r requirements.txt

Não é necessário executar "pip install flask" separadamente se o comando acima
foi executado com sucesso.

Para que serve cada biblioteca:

FLASK
- Framework web principal do projeto.
- Recebe as requisições do navegador.
- Define as rotas, por exemplo /, /login, /estudos e /perfil.
- Renderiza os arquivos HTML da pasta templates.
- Mantém a sessão do usuário durante o login.

REQUESTS
- Faz requisições HTTP para serviços externos.
- No projeto atual é utilizada pelo Assistente Educa para comunicação com a API
  da Groq.

EDGE-TTS
- Gera voz a partir de texto.
- É utilizado nos recursos de fala/áudio do Assistente Educa.

GUNICORN
- Servidor utilizado principalmente em produção, como no Render.
- No desenvolvimento local em Windows você normalmente NÃO precisa executar
  gunicorn; use "python app.py".

PSYCOPG[BINARY]
- Driver para PostgreSQL.
- É utilizado quando o projeto está conectado ao banco Neon/PostgreSQL.
- Localmente, sem DATABASE_URL, o sistema usa SQLite.

6. COMO O PROJETO FUNCIONA — VISÃO GERAL
================================================================================

Fluxo simplificado:

       NAVEGADOR
           |
           v
       app.py (Flask / rotas)
           |
           +--------------------+
           |                    |
           v                    v
       templates/           backend/
       HTML/Jinja           regras e dados
           |                    |
           v                    v
       static/              database/
       CSS, JS, imagens     SQLite ou PostgreSQL

Exemplo real:

1. O usuário acessa:

       http://127.0.0.1:5000/estudos

2. O Flask encontra a rota /estudos dentro de app.py.

3. app.py verifica se o usuário está logado e consulta o progresso no banco.

4. A rota envia os dados para:

       templates/estudos.html

5. O template monta o HTML.

6. O navegador carrega o visual de:

       static/css/app.css
       static/css/acessibilidade.css

7. Quando necessário, a tela também carrega JavaScript, por exemplo:

       static/js/estudos.js

Esse padrão é importante. Não coloque tudo em um único arquivo sem necessidade.
Cada camada tem uma responsabilidade.

8. app.py — O CORAÇÃO DA APLICAÇÃO WEB
================================================================================

O arquivo app.py inicializa o Flask e concentra o fluxo principal do site.

Principais responsabilidades:

- criar a aplicação Flask;
- configurar sessão e cookies;
- chamar a criação/atualização do banco ao iniciar;
- definir as rotas das páginas;
- controlar login, cadastro, recuperação e logout;
- consultar e salvar progresso do aluno;
- renderizar os templates;
- registrar o Assistente Educa.

Algumas rotas importantes:

       /                    Página inicial
       /login               Entrada do usuário
       /cadastro            Cadastro guiado
       /recuperar-conta     Recuperação de senha
       /estudos             Tela principal de estudos
       /estudos/area/...    Área específica de estudos
       /estudos/todos       Catálogo completo
       /trilha/...          Aulas de uma trilha
       /aula/...            Aula interativa
       /perfil              Perfil do usuário
       /sobre               Sobre o Educa+
       /como-funciona       Explicação do funcionamento
       /sair                Encerra a sessão
       /health              Verificação técnica da aplicação

Também existem rotas de API para salvar progresso e conclusão das aulas:

       POST /api/progresso-aula
       POST /api/concluir-aula

REGRA DE MANUTENÇÃO:
Se a alteração envolve URL, login, sessão, redirecionamento ou comunicação entre
uma página e o banco, comece olhando app.py.


================================================================================
9. O QUE SÃO OS TEMPLATES?
================================================================================

Os arquivos da pasta templates/ são as páginas HTML do Flask.

Eles utilizam Jinja, uma linguagem de templates que permite inserir dados vindos
do Python dentro do HTML.

Exemplo conceitual:

       <h1>Olá, {{ nome }}</h1>

O valor de "nome" é enviado pelo Flask quando ele executa render_template().

Os templates também usam estruturas como:

       {% if ... %}
       {% for ... %}
       {% block ... %}
       {% extends ... %}

Não são erros de HTML. São comandos do Jinja.


================================================================================
10. templates/base.html — BASE DE TODAS AS TELAS
================================================================================

base.html é o template principal do site.

Ele contém elementos compartilhados entre as páginas, como:

- estrutura HTML geral;
- cabeçalho e navegação;
- logo;
- menu;
- painel de acessibilidade;
- mensagens globais;
- carregamento dos CSS principais;
- carregamento dos JavaScripts globais;
- blocos que as outras páginas preenchem.

A maioria das telas começa com:

       {% extends "base.html" %}

Isso significa:
"Use base.html como estrutura e coloque o conteúdo desta página dentro dela."

Blocos importantes:

       {% block title %}
       {% block body_class %}
       {% block content %}
       {% block scripts %}

ATENÇÃO:
Um template não deve definir o mesmo block content duas vezes. Isso gera erro do
Jinja, por exemplo:

       TemplateAssertionError: block 'content' defined twice

app.css e acessibilidade.css são carregados pelo base.html.

O acessibilidade.css é propositalmente carregado DEPOIS do app.css para que os
temas acessíveis consigam sobrescrever o visual padrão.

12. templates/acesso.html — LOGIN, CADASTRO E RECUPERAÇÃO
================================================================================

Um único template atende várias telas para evitar duplicação de HTML.

Ele muda de conteúdo conforme a variável "modo" recebida pelo Flask.

Modos utilizados:

- login
- cadastro
- recuperar
- conta_pronta

Isso significa que NÃO é necessário criar quatro arquivos HTML diferentes para
essas telas.

O cadastro atual foi pensado para idosos e utiliza três etapas visuais:

1. nome;
2. celular;
3. senha.

O JavaScript específico dessa área fica em:

       static/js/acesso.js

Observação técnica importante:
A interface não pede e-mail ao idoso. O banco ainda mantém uma coluna "email"
por compatibilidade com versões anteriores, e o backend cria internamente um
endereço técnico. O usuário não precisa conhecer nem preencher esse endereço.

21. backend/banco.py — BANCO DE DADOS
================================================================================

Este arquivo centraliza o acesso ao banco.

Ele decide automaticamente qual banco utilizar:

SEM a variável DATABASE_URL:

       SQLite local -> database/educa.db

COM a variável DATABASE_URL:

       PostgreSQL / Neon

Responsabilidades:

- abrir conexões;
- criar as tabelas se necessário;
- manter compatibilidade com versões antigas;
- normalizar celular e nome de acesso;
- criar usuários;
- adaptar consultas entre SQLite e PostgreSQL.

SQLite já faz parte da biblioteca padrão do Python. Normalmente não é necessário
instalar um programa SQLite separado para simplesmente executar este protótipo.

Quando app.py inicia, ele chama criar_banco(). Portanto, se o arquivo SQLite
local não existir, a estrutura necessária pode ser criada automaticamente.


================================================================================
22. database/educa.db — BANCO LOCAL
================================================================================

É o banco SQLite utilizado no desenvolvimento local.

As principais tabelas atuais são:

usuarios
- dados da conta;
- senha armazenada como hash, não em texto puro;
- login/celular;
- campos de compatibilidade.

progresso_inicio
- mantém referência de progresso de versões anteriores e sincronização básica.

progresso_aula_interativa
- guarda qual aula o usuário está fazendo;
- guarda em qual passo ele parou.

aulas_concluidas
- registra as aulas finalizadas pelo usuário.

A tabela interna sqlite_sequence é criada pelo próprio SQLite para controlar
campos AUTOINCREMENT. Não é uma tabela de negócio do Educa+.

ATENÇÃO:
Não abra o arquivo educa.db em editor de texto comum e não edite bytes
manualmente.

================================================================================
27. VARIÁVEIS DE AMBIENTE
================================================================================

Algumas integrações são configuradas por variáveis de ambiente.

Principais:

DATABASE_URL
- conexão com PostgreSQL/Neon;
- se NÃO estiver configurada, o projeto usa SQLite local.

GROQ_API_KEY
- chave utilizada pelo Assistente Educa para recursos que dependem da API da
  Groq.

EDUCA_SECRET_KEY
- chave usada pelo Flask para proteger/assinar a sessão.
- em produção deve ser uma chave segura e privada.

Também existem configurações opcionais de modelos:

GROQ_MODEL
GROQ_MODEL_FALLBACK
GROQ_WHISPER_MODEL

Para rodar a estrutura principal do site localmente com SQLite, DATABASE_URL não
é obrigatória.

Sem GROQ_API_KEY, partes que dependem da IA/transcrição externa não funcionarão
completamente, mas isso não impede a compreensão e execução das páginas básicas
do protótipo.

NUNCA coloque chaves reais diretamente no código ou envie chaves para o GitHub.

Exemplo temporário no PowerShell:

       $env:GROQ_API_KEY="SUA_CHAVE_AQUI"
       python app.py

Exemplo temporário no CMD:

       set GROQ_API_KEY=SUA_CHAVE_AQUI
       python app.py

Observação:
O projeto atual não depende de arquivo .env para iniciar. Não assuma que colocar
uma variável em .env será suficiente sem configurar um carregador apropriado.

32. CONVENÇÃO PARA HTML SEMÂNTICO
================================================================================

O projeto deve continuar utilizando elementos HTML de acordo com a função do
conteúdo, sempre que possível.

Prefira:

<header>  para cabeçalhos
<nav>     para navegação
<main>    para conteúdo principal, quando aplicável
<section> para seções temáticas
<article> para conteúdo independente, quando fizer sentido
<aside>   para conteúdo complementar
<footer>  para rodapés/ações finais
<button>  para ações executadas na página
<a>       para navegação para outro endereço
<label>   associado a campos de formulário

Evite usar <div> para absolutamente tudo quando existe um elemento semântico
mais adequado.

Isso melhora:

- leitura do código;
- acessibilidade;
- uso por leitores de tela;
- manutenção pela equipe.


================================================================================
33. REGRA IMPORTANTE: LINK NÃO É BOTÃO E BOTÃO NÃO É LINK
================================================================================

Use <a> quando a ação leva para outra página/endereço.

Exemplo:

       <a href="/estudos">Ir para estudos</a>

Use <button> quando a ação acontece na própria interface.

Exemplo:

       <button type="button">Ouvir explicação</button>

Não utilize <div onclick="..."> para substituir botões sem necessidade.
Isso prejudica teclado, leitores de tela e acessibilidade.


================================================================================
34. ACESSIBILIDADE NÃO É UMA FUNÇÃO OPCIONAL DO PROJETO
================================================================================

O público principal do Educa+ são pessoas idosas. Portanto, acessibilidade faz
parte da arquitetura do produto.

Ao desenvolver, preserve:

- textos legíveis;
- contraste adequado;
- foco de teclado visível;
- labels nos formulários;
- aria-label quando necessário;
- alt apropriado em imagens informativas;
- áreas clicáveis confortáveis;
- botões claros;
- linguagem simples;
- suporte a leitura por voz;
- funcionamento dos modos de acessibilidade;
- ausência de dependência exclusiva de cor para transmitir informação.

Não remova atributos ARIA apenas porque parecem "texto extra" no HTML.
Antes, verifique para que servem.

36. COMO O PROGRESSO DAS AULAS É SALVO
================================================================================

Durante a aula, aula.js envia atualizações para o backend.

A API principal de progresso é:

       POST /api/progresso-aula

O backend grava informações em:

       progresso_aula_interativa

Quando a aula é concluída, o navegador utiliza:

       POST /api/concluir-aula

O backend registra em:

       aulas_concluidas

E prepara a próxima aula quando existir.

Isso permite que o usuário retorne depois e continue de onde parou.

37. FLASK + JINJA + JAVASCRIPT: QUEM FAZ O QUÊ?
================================================================================

FLASK / PYTHON
- decide qual página abrir;
- busca dados;
- valida login;
- conversa com o banco;
- entrega dados ao template;
- recebe requisições das APIs.

JINJA / HTML
- cria a estrutura da página;
- mostra os dados enviados pelo Flask;
- decide blocos simples de exibição.

CSS
- controla aparência, layout e responsividade.

JAVASCRIPT
- controla interações no navegador;
- cliques, diálogos e passos;
- comunicação assíncrona com APIs;
- recursos dinâmicos sem recarregar a página inteira.

BANCO
- guarda informações persistentes como usuários e progresso.

Não coloque uma responsabilidade inteira na camada errada.

39. ERROS COMUNS E COMO RESOLVER
================================================================================

ERRO:
'python' não é reconhecido

TENTE:

       py --version

Se também falhar, instale/reinstale Python e verifique o PATH.


ERRO:
No module named 'flask'

CAUSA PROVÁVEL:
Dependências não instaladas no ambiente atual.

SOLUÇÃO:

       python -m pip install -r requirements.txt

Verifique também se o .venv está ativado.


ERRO:
No module named 'requests'
No module named 'edge_tts'
No module named 'psycopg'

SOLUÇÃO:

       python -m pip install -r requirements.txt


ERRO:
PowerShell bloqueia Activate.ps1

SOLUÇÃO MAIS SIMPLES:
Abra CMD e execute:

       .venv\Scripts\activate.bat


ERRO:
Port 5000 already in use / endereço já em uso

CAUSA:
Outro processo já está usando a porta 5000.

SOLUÇÃO:
Feche o outro servidor Flask ou encerre o terminal que já está executando o
projeto.


ERRO:
TemplateNotFound

VERIFIQUE:
- se o arquivo está dentro de templates/;
- se o nome usado no render_template() está correto;
- maiúsculas/minúsculas em sistemas Linux.


ERRO:
TemplateAssertionError: block 'content' defined twice

CAUSA:
O mesmo arquivo Jinja possui dois blocos com o mesmo nome.

SOLUÇÃO:
Mantenha somente um:

       {% block content %}
       ...
       {% endblock %}


ERRO:
Uma imagem não aparece

VERIFIQUE:
- se o arquivo existe em static/;
- se o caminho usado em url_for('static', filename='...') está correto;
- se o nome e extensão são exatamente os mesmos.


ERRO:
A IA não responde

VERIFIQUE:
- GROQ_API_KEY configurada;
- conexão com internet;
- resposta de /api/assistente/local/status;
- terminal do Flask para mensagens de erro.


ERRO:
O site abre, mas /estudos volta para /login

ISSO É NORMAL:
/estudos exige sessão de usuário. Crie uma conta ou faça login primeiro.

44. PRINCÍPIO DO PROJETO
================================================================================

O Educa+ Digital não está sendo construído apenas para "funcionar".
Ele está sendo construído para ser compreendido e utilizado por pessoas que
podem ter pouca familiaridade com tecnologia.

Ao implementar qualquer recurso, pergunte:

- Um idoso entende o que precisa fazer?
- O botão está claro?
- O texto está legível?
- Existe ajuda quando a pessoa tiver dúvida?
- A pessoa pode errar sem medo?
- A informação depende somente de cor?
- O teclado e leitor de tela conseguem navegar?
- A alteração deixa o código mais claro ou mais confuso para a equipe?

A meta é manter duas coisas ao mesmo tempo:

       CÓDIGO ORGANIZADO PARA QUEM DESENVOLVE
                         +
       EXPERIÊNCIA SIMPLES PARA QUEM APRENDE
